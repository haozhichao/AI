# 任务书：三台 VM 每日健康巡检自动化 v0.2

日期：2026-10-30

## 目标

针对一套产品部署环境中的 3 台固定 VM，完成每日健康巡检自动化初版。

巡检脚本运行在一台已获得授权的巡检机器上，通过 SSH 或 PVE9.1 平台相关访问方式采集信息，输出一份 Markdown 巡检报告。

初版要解决的问题：

1. 判断 3 台 VM 是否可以 SSH 登录。
2. 检查每台 VM 的文件系统使用率，识别是否存在使用率超过 85% 的挂载点。
3. 使用 `iostat` 检查 VM 磁盘读写是否繁忙。
4. 检查 VM 对应 PVE9.1 宿主机上关联物理磁盘使用率是否超过 80%。
5. 将正常、异常、失败、无法判断的项目清晰输出到报告中。

## 背景

当前一套产品固定占用 3 台 VM。每天早晨需要人工完成基础巡检，包括 VM 是否可登录、磁盘空间是否充足、磁盘读写是否繁忙，以及 VM 背后关联的宿主机物理磁盘容量是否健康。

VM 均由 PVE9.1 虚拟化平台创建。宿主机信息采集需要同时考虑两种模式：

1. SSH 访问宿主机。
2. Web 端访问 PVE 平台。

初版优先做本地脚本和 Markdown 报告，不做 Web 页面、不做定时任务、不接入告警平台。

## 范围

### 本次包含

1. 读取一份本地配置文件，配置产品、VM、PVE 宿主机和磁盘映射关系。
2. 对 3 台 VM 执行 SSH 连通性检查。
3. 在可登录 VM 上执行 `df -lh` 或等价命令。
4. 解析 VM 挂载点使用率，标记超过 85% 的挂载点。
5. 在可登录 VM 上执行 `iostat`，采集磁盘读写指标。
6. 根据配置中的 VM 与 PVE 宿主机磁盘映射关系，检查宿主机物理磁盘使用率是否超过 80%。
7. 支持宿主机采集方式配置为 `ssh` 或 `pve_web`。
8. 生成 Markdown 巡检报告。

### 本次不包含

1. 不修改 VM、宿主机或 PVE 平台配置。
2. 不自动清理磁盘。
3. 不自动迁移 VM。
4. 不自动扩容磁盘。
5. 不重启服务、VM 或宿主机。
6. 不接入企业微信、邮件或其他告警系统。
7. 不做多产品统一巡检平台，只保留配置结构的扩展空间。

## 约束

1. 所有操作必须是只读操作。
2. 脚本运行机器必须是已授权巡检机器。
3. 不在生产 VM 或宿主机上安装新软件，除非后续明确确认。
4. SSH 账号、IP、端口、PVE 访问方式、VM 与宿主机磁盘映射关系不得写死在代码中，必须放入本地配置文件。
5. 初版只要求手动运行，不要求定时执行。
6. 任意一台 VM 或宿主机访问失败时，不中断全部巡检，应继续检查其他对象。
7. 报告必须区分：
   - 正常
   - 超阈值
   - SSH 不可达
   - 命令执行失败
   - 配置缺失
   - 信息不足，无法判断

## 输入

准备一份本地配置文件，建议使用 YAML。

配置文件至少包含：

1. 产品名称。
2. VM 列表。
3. PVE 宿主机列表。
4. VM 与宿主机的关系。
5. VM 磁盘与宿主机物理磁盘的映射关系。
6. VM 磁盘使用率阈值，默认 85%。
7. 宿主机物理磁盘使用率阈值，默认 80%。
8. `iostat` 繁忙判断阈值。
9. 宿主机采集模式：`ssh` 或 `pve_web`。

示例：

```yaml
product: example-product

thresholds:
  vm_disk_usage_percent: 85
  host_disk_usage_percent: 80
  iostat_util_percent: 80
  iostat_await_ms: 50

vms:
  - name: vm-01
    host: 10.0.0.1
    ssh_user: root
    ssh_port: 22
    pve_host: pve-node-01
    disk_mappings:
      - vm_mount: /opt/local-path-provisioner
        host_storage: local-lvm
        host_disk: /dev/sdb

  - name: vm-02
    host: 10.0.0.2
    ssh_user: root
    ssh_port: 22
    pve_host: pve-node-01
    disk_mappings:
      - vm_mount: /opt/local-path-provisioner
        host_storage: local-lvm
        host_disk: /dev/sdc

  - name: vm-03
    host: 10.0.0.3
    ssh_user: root
    ssh_port: 22
    pve_host: pve-node-02
    disk_mappings:
      - vm_mount: /opt/local-path-provisioner
        host_storage: local-lvm
        host_disk: /dev/sdb

pve_hosts:
  - name: pve-node-01
    access_mode: ssh
    host: 10.0.1.1
    ssh_user: root
    ssh_port: 22

  - name: pve-node-02
    access_mode: pve_web
    web_url: https://10.0.1.2:8006
    note: 初版可先记录访问入口，实际自动采集方式后续确认
```

## 输出

生成一份 Markdown 巡检报告。

报告至少包含：

1. 巡检时间。
2. 产品名称。
3. 巡检对象摘要。
4. VM SSH 连通性结果。
5. VM 磁盘使用率结果。
6. 超过 85% 的 VM 挂载点列表。
7. VM `iostat` 采集结果。
8. 磁盘读写繁忙判断。
9. PVE 宿主机访问结果。
10. 宿主机物理磁盘使用率结果。
11. 超过 80% 的宿主机物理磁盘列表。
12. 配置缺失或映射缺失项。
13. 异常汇总。
14. 建议人工检查动作。

## `iostat` 初版判断规则

初版优先采集并展示原始指标，同时做轻量判断。

建议命令：

```bash
iostat -dx 1 3
```

建议关注字段：

1. `%util`
2. `await`
3. `r/s`
4. `w/s`
5. `rkB/s`
6. `wkB/s`

初版判断：

1. 如果 `%util >= 80`，标记为磁盘繁忙。
2. 如果 `await >= 50ms`，标记为 I/O 等待偏高。
3. 如果命令不存在或输出格式无法解析，报告中标记为“iostat 无法判断”，不阻塞其他巡检。

## 验收条件

本次任务完成后，应满足：

1. 有一份可编辑的巡检配置文件样例。
2. 能对 3 台 VM 执行 SSH 连通性检查。
3. 能采集并解析每台可达 VM 的 `df -lh` 输出。
4. 能识别 VM 上超过 85% 的挂载点。
5. 能执行 `iostat -dx 1 3` 并输出磁盘读写指标。
6. 能基于 `%util` 和 `await` 给出初版磁盘繁忙判断。
7. 能根据配置文件识别 VM 所属 PVE 宿主机。
8. 对于 `access_mode: ssh` 的宿主机，尝试通过 SSH 采集物理磁盘使用率。
9. 对于 `access_mode: pve_web` 的宿主机，初版至少在报告中明确标记访问方式和待确认采集策略。
10. 任意 VM 或宿主机失败，不影响其他对象继续巡检。
11. 生成一份 Markdown 报告，能看出正常项、异常项、失败项和无法判断项。
12. 全程不执行任何写入、清理、重启、扩容或修复动作。

## 失败兜底

如果无法一次性完成全部内容，按以下顺序降级：

1. 先完成 3 台 VM 的 SSH 连通性检查。
2. 再完成 VM `df -lh` 采集和磁盘使用率解析。
3. 再完成 `iostat` 原始输出采集。
4. 如果 `iostat` 解析困难，先把原始输出写入报告，不做自动判断。
5. 如果宿主机 SSH 访问失败，报告中标记失败原因。
6. 如果宿主机为 `pve_web` 模式且暂未接入 API 或自动登录能力，报告中标记为“Web 模式待实现”。
7. 如果 VM 与宿主机物理磁盘映射关系缺失，报告中标记为“配置缺失，无法判断”。
8. 不因为单点失败中断全部巡检。
